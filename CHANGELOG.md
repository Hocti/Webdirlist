# Changelog

## 3.0.0

A full rewrite of the library. Nothing from `2.x` (or the `1.x` line it was renamed from)
carries over unchanged — see below.

### Breaking

- **No more singleton.** `webdirlist.getInstance()` is gone. You now open a listing explicitly
  and can hold as many as you like at once:

  ```js
  // before
  import webdirlist from 'webdirlist';
  webdirlist.getInstance().setCWD();
  await webdirlist.getInstance().loadDir('assets');
  const files = await webdirlist.getInstance().getFileList('assets/audio', {
  	subfolder: true,
  	includedExt: ['wav'],
  	detail: true,
  });

  // after — browser
  import { openManifestDir } from 'webdirlist';
  const assets = await openManifestDir('/assets'); // fetches /assets/files.txt
  const files = assets.files('audio', { includeExt: ['wav'] });

  // after — node
  import { openNodeDir } from 'webdirlist/node';
  const assets = await openNodeDir('./assets');
  const files = assets.files('audio', { includeExt: ['wav'] });
  ```

- **`getFileList()` → `files()`, returning objects, not strings.** Every result is now a
  `FileEntry`: `{ path, name, ext, dir, size, mtime }` (`mtime` in unix seconds). The `detail`
  flag is gone — an entry always carries full metadata, so there's nothing to opt into.
- **Package is ESM-only.** `"type": "module"`, single `import` condition. No CJS build, and no
  UMD/CDN bundle (`dist/webdirlist.js`) — the jsDelivr `<script>` install path in the old README
  no longer works.
- **Node now has its own entry point: `webdirlist/node`.** The default `.` export is
  browser-safe and importing it never reaches `node:fs`. Code that used to run in node against
  the default export must now import from `webdirlist/node`.
- **Renamed option fields** on the (still optional, still per-call) options object:
  - `subfolder` → `subfolders`
  - `includedExt` → `includeExt`
  - `excludedExt` → `excludeExt`
  - `ignoreFolder` → `ignoreFolders` — and it now actually works in the browser. In `1.x`/`2.x`
    it was accepted and documented but silently ignored by the web backend.
- **`loadDir()` → `refresh()`.** Both backends (browser and node) now implement one `DirList`
  interface — `files()`, `folders()`, `get()`, `totalSize()`, `refresh()`, `watch()` — so the
  same code works against either.

### Added

- `folders(dir)` — list immediate sub-directories of a listing. Not available before.
- `watch(listener)` — subscribe to `added` / `changed` / `removed` events. Live on the node
  backend (debounced filesystem watch); accepted but inert on the manifest backend, so calling
  code never has to branch on which backend it has.
- `totalSize(dir, options)` — sum of bytes a query would return.
- `get(path)` — look up a single file by path without a full query.
- `url(path)` (browser) / `absolute(path)` (node) — resolve a listing-relative path to what you'd
  actually pass to `<img src>` or `fs`.
- `tracedir` CLI flags: `--ext`, `--not-ext`, `--skip`, `--flat`, `-h` / `--help`.
- `writeManifest(dir, target?, options?)`, exported from `webdirlist/node`, for calling the
  manifest generator from a build script instead of shelling out to the CLI.

### Fixed

- Default ignore list corrected: `thumb.db` → `Thumbs.db` (the actual filename Windows creates).
- `node_modules` added to the default ignored-folder list.
- `db` added to the default ignored-extension list (alongside `fla`, `psd`, `ai`).

### Unchanged

- The `files.txt` manifest format itself: one file per line,
  `path<TAB>size<TAB>mtime`. A manifest generated by `1.x`/`2.x`'s `tracedir` is still valid
  input — only the JS API for reading it changed.
- Zero runtime dependencies (`path-browserify-esm` is gone; nothing replaced it).
